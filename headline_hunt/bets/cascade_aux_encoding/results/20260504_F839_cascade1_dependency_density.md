# F839 — Cascade-1 5-slot alignment is structurally fully dense (negative)

## What this asks

F14 established that cascade-1 alignment at slots 57..63 ⇒ full sr=63
collision. F15 confirmed no default registry message has cascade-1 at
slot 57+. F16 confirmed random single-axis perturbation can't find one
(17.2 billion negative samples). Conclusion: SAT (kissat) is the right
tool, but it takes ~12h to find one cascade-aligned message.

**Open question that wasn't asked:** does the 5-slot cascade-1 system
**decompose**? Each `dW[k] = cw1[k]` for k ∈ {57..61} depends on some
subset of M[1..15]\{9}. If those subsets are partially disjoint, the
160-bit constraint system splits into smaller staged sub-searches —
fundamentally different from monolithic CDCL.

This memo answers: **no, it doesn't, at any granularity.**

## What we did

Symbolic GF(2) tracking of the schedule expansion. For each W[k] we
track the *linear support* — which (M[i], bit_b) pairs can possibly
influence each bit of W[k]. Modular addition is upper-bounded as union
(carry can only propagate to bits already present in either summand,
so the linear support upper-bounds the true support).

Tool: `headline_hunt/bets/cascade_aux_encoding/encoders/schedule_dep_analysis.py`.

## Results

### Word-level support (every cascade-1 slot touches every M-word)

| slot | n M-words | support |
|---|---|---|
| 57 | 16 | M[0..15] |
| 58–63 | 16 | M[0..15] |

**Pairwise overlap matrix** (slots 57..61): uniform 16. No exclusive
M-words. No sequential decomposition — the first slot alone fixes all
14 free M-words; subsequent slots add zero new constraints by word.

### Bit-level support (per output bit of W[k])

| slot | min | avg | max |
|---|---|---|---|
| 57 | 492 | 508.5 | 512 |
| 58 | 495 | 509.0 | 512 |
| 59 | 498 | 509.9 | 512 |
| 60 | 501 | 510.5 | 512 |
| 61 | 499 | 510.8 | 512 |

(Out of 512 = 16 M-words × 32 bits maximum.)

### Pairwise bit-level overlap (avg M-bits shared between W[k1].bit_b and W[k2].bit_b)

| pair | avg overlap |
|---|---|
| W[57].b ∩ W[58].b | 505.6 |
| W[57].b ∩ W[59].b | 506.5 |
| W[57].b ∩ W[61].b | 507.4 |
| W[58].b ∩ W[60].b | 507.7 |
| W[60].b ∩ W[61].b | 509.3 |

### The 160 × 448 constraint matrix

| metric | value |
|---|---|
| rows (5 slots × 32 bits each) | 160 |
| columns (14 free M-words × 32 bits) | 448 |
| per-row support | min=429, avg=446, max=448 |
| **matrix density** | **0.996** |

The constraint Jacobian is essentially fully dense.

## What this rules out

A dense constraint system has **no exploitable algebraic structure**
for sparse-decomposition methods. Specifically, the following attack
classes are foreclosed at this granularity:

1. **Sequential staged solving** (solve slot 57 first, then 58, etc.):
   no marginal narrowing, every slot constrains all 14 free words.
2. **Sparse Gröbner-basis reduction**: the ideal generated by these
   constraints lives in a maximally-mixed polynomial ring; no
   sparsity to exploit.
3. **Bit-disjoint partitioning**: per-output-bit support saturates,
   no bits are "safe" to fix independently.
4. **Cluster decomposition heuristics** (e.g., tree decomposition with
   small treewidth): the bit-level dependency hypergraph is essentially
   complete-bipartite at this slot range.

## What this validates

This is *consistent with* and explains:

- F16's 17.2-billion-message single-axis sweep finding 0 hits.
- The F213/F214 hard-core decomposition's findings (132 universal
  hard-core bits + structural redundancy noted in `W1_58_universality_confirmed.md`)
  — the residual variance in CDCL behavior is in *carry/state mixing*,
  not in algebraic structure of the schedule.
- The closed 2026-04-25 cb_decide bet (programmatic_sat_propagator/
  phase2c_cb_decide_2026-04-25): no compounding speedup from decision-
  shaping, because the underlying problem has no decomposable
  scaffolding to exploit.
- Why the 31-step record paper (Bright et al. 2024) wins via
  *programmatic SAT* (callback contradiction detection), not
  algebraic preprocessing.

## What this DOESN'T rule out

This analysis tracks **linear support** (upper bound on the support).
The true support is a subset. So:

1. **Cancellation-based sparsity**: specific M-bit values may make
   carry chains terminate early, effectively un-mixing certain output
   bits. CDCL automatically exploits this via unit propagation; the
   analysis doesn't capture it.
2. **Differential-only sparsity**: the dW side (differences only) is
   much sparser than the M side. Kernel cands have only 2 non-zero
   dM-words. The asymmetric structure `f(dM[0], dM[9]) = g(M[0..15])`
   has a sparse left-hand side; the constraint is "specific schedule-
   diff value (LHS, sparse) equals specific state-derived target (RHS,
   dense)." That asymmetry might be exploitable in a different
   reformulation.
3. **Round-by-round structure**: maybe the *temporal* evolution of the
   state (round 56 → 57 → 58 → ...) admits a per-round local fix that
   compounds. F213's hard-core decomposition is in this neighborhood.

## So what direction does this point?

**Toward the differential / kernel-asymmetric reformulation:** the
cascade-1 condition's LHS depends on dM, RHS depends on M, and the
two sides have very different sparsity profiles. A SAT/algebraic
attack that explicitly *separates* the dM and M variable groups —
fixing dM (kernel choice) and searching only over M with the dW
side as a constant — is what kissat already does in our current CNFs.

But there might be a *different* split: fix the STATE at round 56
(via a chosen pre-state), then enumerate which (M[0..15]) reach that
state. The state at round 56 has 8 × 32 = 256 bits; round 56 cascade
constraints (from F14) determine 224 of them via cascade-1, leaving
32 degrees of freedom. So the search becomes: find a 32-bit pre-state
free parameter that's compatible with both cascade-1 alignment slots
57..63 *and* a forward-reachable schedule from M[0..15].

This is closer to a meet-in-the-middle (MITM) attack:

- **Forward**: enumerate M[0..15] → state at round 56 → cascade-1
  conditions (160 bits constraint).
- **Backward**: enumerate cw1[57..63] target schedule diffs → required
  dW[57..63] → required state-derived constants → check forward-feasible
  M.

I haven't seen evidence the project has done this. Worth a follow-up
memo proposing the explicit MITM formulation if the user wants to push
further into algebraic territory.

## Bottom line

The 5-slot cascade-1 alignment problem is structurally as dense as it
gets — essentially complete-bipartite at the bit level. Algebraic
decomposition attacks are foreclosed. CDCL on the dense system is
operationally optimal *for this formulation*; the only remaining
algebraic levers are (a) clever variable group splits (M vs dM, or
state-vs-schedule), or (b) exploiting nonlinear cancellations that
CDCL already gets via unit propagation.

This is a useful negative result: closes a class of attack ideas
and aligns the project's empirical finding (kissat is the right tool)
with a structural reason.
