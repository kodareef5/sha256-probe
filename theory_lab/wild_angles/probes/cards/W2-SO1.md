# W2-SO1 — Neutral-network percolation: search as drift, plateau as a graph bottleneck   ·   VERDICT: KILLED

**Card claim:** The da=0 set is a neutral network (equal-fitness messages; edges = bit-flips that stay on da=0). Collision-finding = neutral DRIFT to HW=0, a pure graph question. The HW~74 plateau = a region with no escape edges to lower HW; all solvers stall at the same HW because they hit the same graph min-cut/conductance bottleneck.

**Probe run:** Built the genuine da=0 message graph from the repo's cascade construction (primitives via shabridge; M0/rotations matched to the N=10 enumerator). In the cascade, path-2's tail is *determined* by path-1 (find_w2 enforces da=0 each round), so da=0 holds for EVERY path-1 tail (w57..w60) — the neutral manifold is the full 4N-bit tail hypercube, edges = single-bit flips, fitness = output-difference Hamming weight HW. Verified 50/50 CSV collision tails reproduce HW=0. Then measured (1) the HW distribution vs Binomial, and (2)/(3) the per-HW neighbor census (neutral / down / up edge fractions) to locate any bottleneck. N=10, throttled (OMP=2, taskpolicy -b), ~minute.

**Result (numbers):**
- **(1) HW is Binomial random bits.** Over 40k random tails: mean=**30.0**, std=**4.48**, range 11–47 (of 80 output bits). Effective k if HW~Binomial(k,½): k_from_mean=**60.0**, k_from_var=**80.1** — both ≈ the output-bit count, i.e. the HW is plain coin-flip bits. Modal HW=30 (the N=10 analog of the HW~74 plateau at N=32); a "descent" below mean−2σ has probability **0.027** (a rare Binomial-tail event, exactly the random-search difficulty).
- **(2)/(3) No bottleneck — perfectly smooth descent gradient.** The DOWN-edge fraction (escape toward lower HW) rises *smoothly and monotonically* with HW: 0.8% at HW=18 → **45.7% at the modal HW=30** → 96–99% at HW≥40. At the plateau HW, DOWN%≈UP%≈46% — the detailed-balance crossing of a random walk on a Binomial ladder, NOT a conductance collapse. There is no sharp min-cut anywhere.
- **The "neutral" network is barely neutral:** neutral-edge fraction peaks at only **~9%** (at the mode) and is <2% in the tails — a tail almost never has an equal-HW neighbor, so lateral neutral *drift* (the card's mechanism) is essentially absent.

**Kill_criterion:** "Dead if the network is one well-mixed component with constant conductance and poly drift to HW=0, OR the plateau doesn't coincide with the min-cut." — **fired? YES.** It is the connected tail-hypercube with a smooth (Binomial) descent gradient — no min-cut at all — so the plateau coincides with no bottleneck; it is simply the random-bit mode where up/down flips balance.

**Verdict reasoning:** KILLED, and the answer to the lead's framing is explicit: **SO1 RENAMES the plateau, it does not add a mechanism.** The output-difference HW is Binomial(≈132-analog, ½) — exactly the repo's "132 hard-core bits behave as random draws" model — and the supposed graph bottleneck is illusory: the DOWN-edge fraction crosses 50% *exactly at the modal HW* by detailed balance, with no conductance collapse, no isolated low-HW component, and only ~9% neutral edges. So "plateau = graph min-cut" is false; the plateau is the entropic mode of a coin-flip distribution, re-described as a hypercube. The reframing buys nothing the random-bit picture didn't already give.

**Cross-check / skeptic note:** The card's own skeptic line — "the network may simply be *disconnected* across HW levels … 'drift' is a non-starter; the edge definition is load-bearing" — is borne out: at fixed HW, neighbors are overwhelmingly UP/DOWN (≥90% combined), so there is almost no equal-fitness sub-graph to drift on; motion is forced biased-random-walk, not neutral drift. Two independent readouts agree the mechanism is absent: the HW moments match Binomial (k≈60–80 from both mean and variance), and the neighbor census shows a smooth gradient rather than a cut. Caveat: tested at N=10, where the plateau analog is HW≈30; the structure (Binomial, smooth descent) is N-generic and matches the repo's N=32 floor (HW~74–76) under the same 132-random-bits law — there is no reason a true min-cut would appear only at N=32 when none exists at N=10.
