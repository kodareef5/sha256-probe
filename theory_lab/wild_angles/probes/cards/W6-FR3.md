# W6-FR3 — de58 set-renormalization -> width-(N+1) collisions contain scaled width-N copies   ·   VERDICT: KILLED

**Card claim:** If the collision set is self-similar, each de58 class at width N+1, rescaled (drop one bit), = the full width-N collision set; the growth |de58|(N) is the renormalization branching, and C(N+1) ≈ 2^0.74·C(N) is its fixed point (intercept 2.47 = seed measure). A constructive lever (build N+1 from N).

**Probe run:** Enumerated the full da=0 sr=60 collision sets exactly: N=8 via a lab-side exact C dump (`_w6fr_dump.c`, a READ-ONLY copy of the repo's `gap_analysis.c` enumeration → 260 collisions, with per-collision de56/db56/de57/de58/de59/de60); N=10 via the repo's 946-collision corpus (`gap_rows.csv`) replayed through the repo-faithful engine to recover de58 (all 946 re-verified as collisions). Tagged each collision by de58 class. Tested a PRE-SPECIFIED bit-shift projection P: N=10 word-tuples → N=8 (drop the top 2 bits, and separately the bottom 2 bits), and measured multiset overlap of P(coll_N10) with the N=8 collision set, globally and per-de58-class, against a random null. Throttled.

**Result (numbers):**
- **de58-class structure:** N=8 → exactly **8** distinct de58 classes (matches |de58|=8); N=10 → exactly **16** classes (matches |de58|=16). Class sizes irregular (N=8: 59..15; N=10: 75..43). de58 = 8 at N=8 despite hw(db56)=4 (would give 2^4=16) — a carry-collapse, so even "2^hw(db56)" is not exact here.
- **Self-similar nesting (the load-bearing test):** global projected overlap P(coll_N10) ∩ set_N8 = **0.0000 (0 of 946)** for BOTH shift directions (drop top 2 bits; drop bottom 2 bits). Random null overlap was 6.05e-8, so even a single hit would have been notable — there were none.
- **Per-class nesting:** every one of the 16 N=10 de58 classes → **0.0000** overlap with the N=8 set (best of both shifts). No class nests.
- **Growth ratio:** C(10)/C(8) = 946/260 = **3.638**, vs the card's fixed-point prediction 2^(0.74·2) = 2.789 (observed effective slope 0.932, not 0.74).

**Kill_criterion:** "down-projected classes don't nest (overlap <50%, no consistent scaling map)." — **fired? YES, decisively (0% overlap, not merely <50%).**

**Verdict reasoning:** KILLED. The claimed exact set self-similarity A_{N+1}|class ≅ scale(A_N) is false: no pre-specified bit-shift map (either direction) sends any width-10 collision — or any width-10 de58 class — onto the width-8 collision set; the overlap is exactly zero, globally and per class. The de58 partition is genuine and clean (8 classes at N=8, 16 at N=10, matching |de58|), but it is NOT a renormalization fixed point: the class *values* live at different word widths with no scaling identity, the class sizes are irregular, and |de58| itself is non-monotone/carry-collapsed (prior finding #5: |de58| = carry-collapsed Maj-image count, e.g. 8 at N=8 vs the naive 2^hw=16). The growth ratio (3.64) does not match the 2^0.74 fixed point either (it matches the same ≈2^0.93 LSB-freedom base found in W6-FR1, not a self-similar branching). The card *restates* the de58 partition as "renormalization" but derives no self-similar structure and no constructive N→N+1 lever.

**Cross-check / skeptic note:** The map was pre-specified (a pure bit-shift, both directions tested) exactly to avoid the "both sets are biggish" degeneracy the card's own skeptic line warns about — and it returned a hard zero, which is the strongest possible negative (not a soft sub-threshold). Independent corroboration the de58 thread is not self-similar: the class *count* sequence {2,8,8,16,512,...} is non-monotone (12→512, 13→32 in the pinned DE_SIZES), incompatible with any single renormalization branching ratio; and the N=8 collapse to 8 classes (not 16) shows the structure is set by carry absorption (hw of db56 after collapse), not by a clean rescaling of a width-N seed. What would change the verdict: a pre-specified scaling map (need not be a bare bit-shift) under which width-(N+1) de58 classes reproduce the width-N collision multiset with >80% overlap AND a |de58| growth that is monotone/derivable — neither holds.
