**Probe run:** Full width N=32 (the 132 is a 32-bit phenomenon — the literal-132 question). Throttled (OMP=2, taskpolicy -b). Computed its genuine GF(2) rank and corank (= left-null / self-stress dim). Ran the single-bit deterministic census (the repo's 132 protocol) side-by-side as the adjudicator.

**Result (numbers):**
- **Genuine LINEAR corank (the card's actual object):** single base point rank **128 / corank 128**; union over ≥5 base points rank **256 / corank 0** (full controllability). **Never 132**, and not stable (128 → 0 as base points are added).

- **Support overlap test:** the generous LINEAR left-null is **0-dimensional (empty)** — so there is no linear self-stress subspace whose support could overlap the hard-core positions. The 132's support is real but belongs to the *census*, not to any cokernel.

**Kill_criterion:** "Dead if self-stress dim doesn't scale toward 132 at N=32, OR its support doesn't overlap the hard-core positions above chance." — **fired? YES.** The genuine rigidity-matrix left-null dim is 128/0 — it does **not** scale toward 132; and the generous linear left-null is empty, so there is no self-stress support to overlap.

So "self-stresses = the 132 hard core" relabels the carry census as a linear corank; it is not a real self-stress dimension, and the predicted rank≈124 is wrong (the true linear rank is 256). KILLED as a mechanism (the number 132 survives, but only as the carry census, not as a rigidity-matrix left-null).
