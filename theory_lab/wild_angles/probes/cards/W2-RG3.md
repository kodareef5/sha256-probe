# W2-RG3 — Pebble-game generic rigidity → rigid clusters = forced cores, explains the linearization timeout   ·   VERDICT: SURVIVES (with caveat)

**Card claim:** Build the (k,ℓ)-pebble-game carry-coupling graph; maximal rigid clusters = uncontrollable forced sub-structures. Run on TRUE and XOR-linearized wiring — **clusters should be ~identical** (explaining why XOR-linearized sr=60 still timed out: "geometry not length"). Gives a sub-quadratic predictor of which words are floppy.

**Probe run:** N=8,12,16 (and single-round N=8,12), throttled (OMP=2, taskpolicy -b). Built a *sparse, faithful* tail coupling graph where the **only** structural difference between TRUE and XOR-linearized is the carry ladder: each modular adder a'=T1+T2, e'=d+T1 contributes per-column co-occurrence cliques + Sigma rotation cross-links (linear, identical in both wirings), and TRUE additionally chains consecutive output columns z[k]↔z[k−1] (carry propagation). Ran the **(2,3) Lee–Streinu pebble game** (canonical 2D bar-joint rigidity matroid — NOT fit to 132; validated on triangle/K4/K5/path ground-truth cases) on both wirings; reported rigid-cluster sizes, component count, matroid rank (= #independent edges), and redundant-edge count.

**Result (numbers):**
- **Percolates fully.** TRUE graph is a **single rigid component spanning all V** at every N (biggest-cluster fraction = 1.000; ncomp=1). Rank = #independent edges = **2V−3 exactly** at every N (253=2·128−3, 381=2·192−3, 509=2·256−3) → the graph is *minimally generically rigid*.
- **TRUE vs XOR-linearized are IDENTICAL.** Same rank (253/253, 381/381, 509/509 — max divergence **0**), same single full component, at every N. The carry-ladder edges (|E|: 770→672, 1162→1008, 1554→1344) are **entirely absorbed as redundant** (redundant: 517 vs 419, 781 vs 627, 1045 vs 835) — they add zero rigidity-matroid rank.
- Single-round network behaves the same (32 verts, rank 61=2·32−3, one component, carries redundant) — robust, not a full-tail artifact.

**Kill_criterion:** "Dead if clusters don't percolate near the boundary, OR true-vs-linearized graphs differ a lot (carry length mattered after all), OR (k,ℓ) needs ad-hoc tuning." — **fired? NO** on all three. Clusters percolate (single spanning rigid component); TRUE vs LINEAR rank divergence is exactly 0 (identical); (2,3) is the canonical matroid, untuned.

**Verdict reasoning:** The kill criterion does **not** fire, so the angle SURVIVES: the carry-coupling graph percolates into one rigid cluster, and that cluster is *identical* under TRUE vs XOR-linearized wiring — exactly the card's falsifiable prediction "clusters ~identical, so linearization doesn't help." The mechanism is concrete: **the carry ladder is rigidity-redundant** — the Sigma rotation skeleton alone already makes the graph minimally generically rigid (rank 2V−3), so dropping carries (XOR-linearization) removes only redundant edges and leaves the rigid structure intact. This is a genuine, independent corroboration of W1-PH2 / the repo finding that XOR-linearization preserves the combinatorial skeleton ("geometry not length"). **Caveat (why SURVIVES, not CONFIRMED):** the graph is ONE rigid component with *nothing floppy* — so the card's promised payoff, a floppy/forced split predicting *which words are free*, is NOT delivered (everything is "forced"). And "carries are redundant for rigidity" is subtly weaker than "the rigid core is what makes collisions hard": it explains why linearization is *harmless to rigidity*, not why the problem is *hard*. So the angle is consistent and worth a deeper probe (a (k,ℓ) that exposes a non-trivial rigid/floppy partition, e.g. on a less skeleton-dominated graph), but it has not positively produced the forced-core predictor.

**Cross-check / skeptic note:** The pebble game was validated against four exact rigidity ground truths before use (triangle→3 indep/0 redundant; K4→5/1; K5→7/3; path→3/0), so the matroid rank is trustworthy. The main skeptic risk is graph-construction dependence: a *denser* graph (my first attempt, with full rotation cliques) also gave true≈linearized but trivially (near-complete, mostly redundant) — and this sparse version still gives identical clusters, so the conclusion is robust to that choice. The deeper limitation is that any reasonable wiring graph here is rotation-skeleton-rigid, so "carries redundant" may be a property of *any* such graph rather than a special feature of SHA — which is why this is SURVIVES (consistent) rather than a positive CONFIRMED of a forced-core predictor.
